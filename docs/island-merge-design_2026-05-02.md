# 🏝️ Word Island Builder — 融合设计方案 v1.1

**设计目标**：将 LearningIsFun 的词汇学习系统与岛屿建造玩法深度融合，打造"背单词→建造岛屿"的完整闭环。

---

## 📋 已确认决策 (2026-05-24)

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 技术框架 | ✅ **模块化** Vite + Vanilla JS（非单HTML） |
| 2 | 地图视角 | ✅ **俯视 top-down**（非等距 isometric） |
| 3 | 词汇来源 | ✅ **完全复用** LearningIsFun 词库+SM-2算法 |
| 4 | 功能范围 | ✅ **全部功能**，分阶段交付 |
| 5 | 旧数据处理 | ✅ **全新开始**，不迁移 |
| 6 | 离线收入 | ✅ **做**，上限8小时，10%倍率 |
| 7 | 建筑Buff | ✅ **先做3-5种核心建筑** |
| 8 | 数值体系 | ✅ **独立设计**，不绑定 FunIsland V3 |

## 一、核心设计支柱

### 1. 每个词汇都是建材
**玩家幻想**：我的词汇量直接可视化为我创造的岛屿世界。学得越多，世界越丰富。

### 2. 建造即复习
**玩家幻想**：建造建筑时触发词汇回忆，让复习成为建造过程的自然组成部分。

### 3. 经济驱动学习
**玩家幻想**：我需要更多资源来建造梦想岛屿，学习新词是获取资源的主要途径。

## 二、核心游戏循环

### 即时体验（0–30秒）
```
行为：刷一张单词卡片
反馈：卡片翻转动画 + 音效 + "建材+1" 浮动提示
奖励：获得对应建材（gold/wood/stone/star）
```

### 单次会话循环（5–15分钟）
```
目标：完成今日刷词任务 → 积累建材 → 建造/升级一座建筑
紧张感：建筑有"词汇需求"——必须掌握足够词汇才能建造
结局：岛屿升级动画 → 解锁新建筑类型 → 预览下一个目标
```

### 长期循环（数周–数月）
```
成长：
  - 词汇王国等级（Lv.1 新手岛 → Lv.10 词汇帝国）
  - 建筑解锁树（树木 → 小屋 → 市场 → 城堡 → 奇迹）
  - Leitner 盒子分布可视化

留存钩子：
  - 每日签到奖励（连续签到有 bonus）
  - 建筑升级队列（倒计时创造"回来看"的动力）
  - 成就系统（"词汇领主"、"建造大师"等徽章）
```

## 三、融合机制设计

### 机制A：词汇→建材映射

**目的**：将抽象的词汇学习转化为具象的资源积累

**资源体系（4种）**：

| 资源 | 图标 | 用途 | 来源 |
|-----|------|------|------|
| 🪙 Gold | 金币 | 通用消耗 | 复习大多数词 |
| 🪵 Wood | 木材 | 基础建材 | 复习基础词、🪓产出 |
| 🪨 Stone | 石材 | 高级建材 | 复习高级词、⛏️产出 |
| ⭐ Star | 星星 | 解锁新建筑种类 | Box 5 词汇里程碑 |

> ⭐ 星星来源：每个 Box 5 词每复习一次给 1⭐。星星是"解锁凭证"，花钱+有足够星星才能建高级建筑。

**映射规则（基于 Leitner Box）**：

| Leitner Box | 记住奖励 | 模糊奖励 | 不会处理 |
|-------------|---------|---------|---------|
| Box 1 (🔴) | gold+2, wood+1 | gold+1 | 归零重来 |
| Box 2 (🟡) | gold+3, wood+2 | gold+1, wood+1 | 打回Box 1 |
| Box 3 (🟢) | gold+5, wood+3 | gold+2, wood+1 | 打回Box 1 |
| Box 4 (🔵) | gold+8, wood+5, stone+3 | gold+3, wood+2 | 打回Box 1 |
| Box 5 (🟣) | gold+12, wood+8, stone+5, star+1 | gold+5, wood+3, stone+1 | 打回Box 2 |

### 机制B：建造触发复习

**目的**：让建造过程成为自然的复习机会

**流程**：
```
1. 玩家选择建造"小屋"
2. 系统检查资源 + 词汇解锁条件
3. 条件满足 → 直接建造
4. 条件不满足 → 提示"再背 N 个词解锁"
```

**建筑词汇需求表（核心建筑）**：

| 建筑 | 花费 | ⭐需要 | 词量需求 | 解锁条件 |
|-----|------|-------|---------|---------|
| 🌲 树木 | 5g | 0 | 0词 | 开局可用 |
| 🪓 伐木场 | 10g | 1 | 5词 | 掌握5词 |
| 🏠 小屋 | 50g/20w | 2 | 10词 | 10词里程碑 |
| ⛏️ 采石场 | 50g/20w | 10 | 50词 | 50词里程碑 |

### 机制C：建筑产出词汇Buff

**目的**：赋予建筑功能性价值，创造策略选择

**核心建筑效果（MVP阶段）**：

| 建筑 | 建造花费 | 被动收入(per 6s) | 学习Buff | Buff说明 |
|-----|---------|-----------------|---------|----------|
| 🌲 Tree | 5g | — | — | 纯装饰，开局可建 |
| 🪓 Lumberjack | 10g | wood:1 | 柴火效应 | 每有1个🪓，学自然类词wood+1 |
| 🏠 Cottage | 50g/20w | gold:1 | 家的温暖 | streak连续3天，每日gold+10 |
| ⛏️ Quarry | 50g/20w | stone:1 | 凿石 | 每有1个Quarry，学science词stone+1 |

### 机制D：岛屿等级系统

**目的**：可视化长期成长，创造里程碑动力

**等级表**：

| 岛屿等级 | 名称 | 所需词汇 | 解锁内容 |
|---------|-----|---------|---------|
| Lv.1 | 新手小岛 | 10 | 🌲 树木、🪓 伐木场 |
| Lv.2 | 词汇村庄 | 25 | 🏠 小屋 |
| Lv.3 | 繁荣小镇 | 50 | 🌷 花园、⛏️ 采石场 |
| Lv.4 | 工业城市 | 100 | ⚓ 码头、💎 深矿 |
| Lv.5 | 词汇王国 | 200 | 🏪 市场、🗼 灯塔 |

**视觉反馈**：
- 每升一级，岛屿地图扩大一圈
- 新地形类型解锁（草地→沙滩→浅水→深水）
- 建筑高度上限提升

### 机制E：离线收入

**目的**：让玩家"睡一觉也有收获"，提高留存

**规则**：
```
在线模式（正在刷词/建造）：
  建筑产出 = 基础 income × 1.0（全速）

离线模式（没打开游戏）：
  建筑产出 = 基础 income × 0.1（10% 速度）
  最多累计 8 小时的离线收益
  打开游戏时一次性结算
```

**防作弊**：记录 `lastOnline` 时间戳，改系统时间无效（需服务端验证，MVP阶段先客户端）。

## 九、风险与对策

### 风险1：学习压力感
**问题**：建造需求词汇过多，让玩家感到学习是负担
**对策**：
- 设置合理的词汇门槛曲线
- 装饰性建筑无需词汇
- "复习加速"可选而非必须

### 风险2：经济崩溃
**问题**：词汇太多导致资源泛滥，建造失去挑战
**对策**：
- 资源产出随岛屿等级递减
- 高级建筑需要稀有资源（⭐星星）
- 定期检查"每活跃玩家日均资源"指标

### 风险3：玩法割裂
**问题**：刷词和建造两个系统感觉分离
**对策**：
- 强化视觉关联（建材浮动提示、建筑词汇主题）
- 建造时强制复习3词
- 建筑命名与词汇关联（如"图书馆"需要"book"相关词）

### 风险4：模块化过度设计
**问题**：Vite 脚手架反而拖慢开发速度
**对策**：
- MVP 阶段保持文件数量 ≤ 10 个
- 不引入框架，纯 Vanilla JS
- 模块化只为编译检查和 import 安全，不是为了"优雅架构"

## 十、设计总结

### 为什么这个融合会成功？

1. **正反馈循环**：学习→建材→建造→成就感→更多学习动机
2. **可视化成长**：词汇量不再是数字，而是可见的岛屿世界
3. **有意义的选择**：先建什么？复习哪些词？策略深度
4. **长期留存**：解锁树、成就系统、连续签到

### 核心差异化

- **vs 纯刷词APP**：我们有建造玩法，词汇有物理意义
- **vs 纯建造游戏**：我们有学习价值，家长支持孩子玩
- **vs 其他教育游戏**：我们深度融合而非简单叠加
